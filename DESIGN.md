# Codex Strip / Design v2

References: VoltAgent awesome-design-md, Linear (hierarchy, restraint) and Apple (light materials). MIT attribution included in the installed design skill.

Compact horizontal task monitor. Header 44px, card top padding 8px, metadata row 28px, title height determined by one or two actual lines, recency row 20px. Remaining height goes to progress text. Minimum window 420×210; minimum card width 260px with horizontal scrolling. No chat controls.

Light: canvas #F5F5F7, surface #FFFFFF, hover #F0F0F5, ink #202126, secondary #656773, hairline #E3E3E9, action #5856D6. Dark: canvas #111113, surface #1B1B1F, hover #25252C, ink #F4F4F6, secondary #A2A2AE, hairline #303036, action #A5A1FF. Semantic green and amber are separately tuned per theme.

Segoe UI and Microsoft YaHei UI; 11px metadata, 13px progress, 17px task title, 24px window headings, 48px quota. Spacing 4/8/12/16/24. Radius 8px controls, 12px surfaces. Hairlines only on surface edges; no gradients or decorative glows. Focus ring uses action accent. Every popup shares the theme and control system.

Theme options: system / light / dark, persisted. Settings are immediate; count uses a bounded stepper, hosts and themes use explicit choices. Quota separates weekly reset from reset-card expiry and emphasizes the earliest card. Demo snapshots are marked as demonstration data.

Attention cards: waiting for input, approval and reconnect/sync use a full amber surface, 2px outline, alongside the textual state badge. Capacity errors use the same geometry in red. Light amber fill/hover/edge: #FFF4DE / #FFEBC2 / #C99532; dark: #302719 / #3C301D / #A47E3C. Light red: #FFF0F0 / #FFE4E4 / #CF6870; dark: #342124 / #41272C / #B85D68. Keyboard focus retains the action accent; hover preserves semantic color; disabled opacity is 0.5. No flashing or animation. Normal cards remain neutral. The change adapts Linear's surface hierarchy to a desktop status monitor, using semantic color only for attention states.

Verified this change with native WPF renders at 1280px in light/dark and 600px in dark. Titles, badges and preview text fit; compact mode scrolls horizontally. Secondary windows are unchanged.

Completed unread results: green full-card highlight, same 2px outline, with “完成 · 未查看”. Light fill/hover/edge: #EAF8F0 / #DCF1E5 / #4A9871; dark: #192F28 / #203D32 / #529D7B. Uses the desktop hasUnreadTurn state only when the latest turn is completed. A read-state patch removes the highlight; active or failed turns do not use this treatment. Both themes rendered and inspected at 1280px; projection and read-delta behavior tested.

Read-state correction: prefer the desktop's separate canonical unread store over potentially stale conversation snapshots. Read-state broadcasts update the cache; a separate 2-second refresh reconciles persisted blue-dot state. Verified against the live local/Virgo store and actual UI: previously read completions have no green highlight. No message submission is needed.

Inset panels replace separate windows and native tooltips. Preview opens on task-card right click; right-clicking the preview or the same task again closes it. Hover does nothing. Preview alone compresses tasks to a 216px rail (128px in compact windows). Quota and settings instead appear as an additional wider card beside horizontal task cards, targeting roughly 1.65 task widths with a compact-screen minimum. Their toolbar buttons show selection and toggle their respective card closed on the next click. Switching tools replaces the auxiliary card. Both layouts use a 300ms smoothstep ease-in/out transition, remain clipped to application bounds, and support Escape/close as alternatives. Preview supports selection/copy and basic Markdown. Respect Windows ClientAreaAnimation preference.

Scrollbars: 10px layout gutter, transparent track, rounded muted thumb at 45% opacity, no arrow buttons; horizontal and vertical orientations use the same light/dark palette. Secondary panels use the same surface and type hierarchy as cards. Verified WPF rendered light 1280×286 and dark 600×210; runtime tests cover intermediate animation width, containment, a single native window, theme switch, resize, long-content scrolling, and return to cards.

Utility density: quota uses two columns when its card is at least 320px wide, placing weekly allowance beside reset-card expiries. Narrower cards stack the sections. Settings use four compact rows with a 58px label column and controls in the remaining width. At 1280×286, all four settings and three demo reset cards are visible without vertical scrolling; at 600×210, overflow stays inside the card. Light/dark renders inspected.

Card animation correction: utility toggles preserve existing task-card controls. Each column follows the actual animated viewport width, including smoothly changing minimum widths for compact windows, instead of jumping to target widths. Verified intermediate rendered card widths, monotonic shrink, reverse expansion, control identity, and rapid open/close/switch interactions.

Scrollbar stability: task horizontal scrollbars are explicitly enabled only when minimum card widths require overflow, not based on transient automatic layout measurements. Equal-width utility switches skip redundant width animations. Internal body width follows the actual window width on resize. Verified 184 rendered frames across wide/compact utility switches with no unexpected scrollbar visibility changes; compact horizontal scrolling and card animations still work. The topmost toggle aligns left with the host/theme controls.

Vertical scrollbar stability: inset contents lay out at their target width/height inside a clipped, non-measuring Canvas while the outer region animates. This prevents temporary narrow-width wrapping from triggering vertical scrollbars. Verified 165 rendered frames at 1280×286 with zero vertical scrollbar frames across utility opening/switching; theme, resize, long-preview scrolling and containment regression checks pass. Genuinely overflowing content in smaller windows can still scroll.

Equal task widths: task cards have no asymmetric outer margins. Dedicated 10px columns separate equal-width card columns; available width is divided only after subtracting gaps. Checked actual card widths within one layout pixel across normal, auxiliary-card, restored and compact layouts. Animation and scrollbar regression checks pass.

Portrait adaptation: height > width selects a vertical layout. Task cards have equal widths/heights and dedicated 10px row gaps; minimum card height is 140px, with vertical scrolling when necessary. Quota/settings expand as a taller top card; preview condenses tasks at the top. The existing 300ms animation runs on row height, preserving task controls. Panel contents remain at final dimensions inside clipping containers. At widths below 400px the brand name hides; secondary header text hides below 560px to keep controls accessible. Minimum width 320px. Quota uses two columns in portrait. Light 420×1000 and dark 320×900 rendered; tests cover equal cards, animated height, right-click and button toggles, theme, orientation changes while a panel is open, and window containment. Landscape equal-width, animation and scrollbar regressions pass.

Windows AppBar: defaults to top docking on the selected/current monitor. Display and Dock controls share one adaptive settings page. Users choose floating/top/bottom/left/right, monitor and independent horizontal/vertical thicknesses. Uses native monitor rectangles and per-window DPI, AppBar registration/query/set/remove, shell position callbacks and Explorer-restart handling. Hiding/closing releases reserved work area; showing reserves again. Floating shrinks to 78% near the previous dock edge, bounded by minimum size and current monitor work area. Verified real Windows work-area changes on all four edges and connected monitors with the production DPI manifest, maximized test-window avoidance, hide/show/dispose cleanup, and actual StripWindow portrait/landscape docking.

Window priority has three explicit choices: normal, above ordinary windows with fullscreen yielding, and persistent topmost. Same-monitor foreground fullscreen detection runs every 250ms; exclusive fullscreen overlays are not guaranteed. Header transpose swaps floating dimensions, or top/left and bottom/right docking. Verified with a separate-process fullscreen window, four-edge nearby floating, actual StripWindow transpose, and compact 320px light/dark settings renders.

Unified settings: two equal section columns at a panel width of 620px or more; otherwise a single continuous page. No display/dock page switch. Internal native vertical bars are replaced by directional edge fades and a centered 56px track with a proportional 3px rounded position thumb; clicking the track seeks through content. The indicator disappears when content fits. Settings title is simply 看板设置. Compact light/dark renders and adaptive scroll-position checks passed. Online reference retrieval was unavailable during this refinement; no newly fetched case study is claimed. Wheel/touch scrolling and preview text selection remain available. Portrait quota/settings sit above the tasks, while preview keeps its task list above the reading area. Verified adaptive columns, scroll reachability/position feedback, top placement after theme changes, preview order and portrait switching.




Adaptive transpose: preserve long-axis work-area coverage. Thickness uses independent per-Windows-display horizontal/vertical memory in logical pixels; first vertical width 320, horizontal height 286. No aspect-ratio multiplier. Manual floating resize completion and dock thickness controls persist the chosen thickness. Verified real floating/dock transpose, 320px default, custom 360px portrait and 260px landscape restoration, serialization, separate monitor records, DPI and screen bounds.

Transpose icon: outlined window with a quarter-turn arrow, visually distinct from settings sliders. Retains 16px line icon scale and existing click target. Verified rendered 320px light/dark headers.

Idle resource page: replace the entire task dashboard when quiet, including its toolbar. Use the active light or dark theme and one shared metric surface with hairline dividers. Keep a status title, return hint, clock, and explicit return control above the data. CPU, GPU, and memory default to one ring: the used angle is split into shades of one accent for processes and a residual group, while the unoccupied angle stays neutral gray. A compact legend names the largest processes. Keep network and disk as rate readings, with one primary and one secondary value. Narrow portrait windows use one metric per row; compact landscape windows scroll metrics horizontally at a readable minimum width. User-selected images sit behind a dim layer and a readable data surface. The settings page keeps automatic switching and delay visible, with resource, wallpaper, and color controls behind an explicit expand control. Review real WPF renders in light, dark, wallpaper, compact landscape, and portrait sizes.

Resource ring motion: keep sampling at one-second intervals and animate only the ring geometry at about 30 frames per second. A damped second-order response retains velocity when a new target arrives, with bounded speed and acceleration; the total and named process segments each follow their own target. Stop the animation when settled or when the resource page is hidden. Offer an immediate mode for users who prefer a static readout.
